## 실행 환경

- 브라우저: `http://localhost:5178`. 로그인 쿠키 때문에 `127.0.0.1`로 바꾸지 않는다.
- server 8000 → diagnosis 8030 / route 8010.
- 기존 PostgreSQL 데이터와 볼륨을 유지했다. 시험을 위해 초기화하지 않는다.
- 문진과 업체 검토 모두 Azure 실제 호출. 기업·물량·수락·출력 근거는 합성 시험자료.
- 코드와 함께 모델 대기 60초, server 문진 대기 300초를 적용했다. SDK 중첩 재시도는 0회, 추출·응답의 기존 재시도와 대체 응답은 유지한다.
- diagnosis 준비 상태가 정상이 된 뒤 server를 시작한다.
- 최종 web만 재빌드할 때는 `docker compose up -d --build --no-deps web`을 사용했다.
- 실제 적재 참조 DB: 시설 62곳 / 공정 전환 69개 / 연결 129개. 참조 체크섬: `b723a79107b67de536704b5b317b5bbde5d7c84536dea31eb7008e30835f0ec3`.

## 결과

- PP 직접 종료: 1,000kg → 별도 수신기업 수락·QR 입고 → 펠렛 920kg 완료.
- PP 두 단계: 1,000kg → B 조건부 수락·추가자료·최종수락·QR → 파쇄품 950kg → C 수락·두 번째 QR → 펠렛 900kg 완료.
- 업체 AI 검토: 직접 경로 9곳 / 두 단계의 A 14곳 / B 9곳 전체 검토 완료. 이것은 업체 허가·이번 반입 승인을 뜻하지 않는다.
- 서버를 다시 시작해도 A·B·C가 같은 완료 상태와 사진을 볼 수 있는지 15개 검사 통과.
- 자동 검사: web 61 / server 487 / diagnosis 677 통과. route는 이전 코드 검사 566 통과·72 생략·24 subtests 결과를 유지하고 실제 Azure 연결을 통합 검증했다.
- 18개 소재의 문진→분류→R유형→형태별 조회: 56개 형태 중 53개에 후보. 위험조건 11개는 일반 경로 진입 보류.
- 동시 문진 중 기존 30초 제한에 걸린 5건은 제한·재시도 수정 후 모두 통과했다. 실패 로그와 재검사 결과를 따로 보존했다.

## 미완료 범위

Google·Microsoft OAuth는 서버 앱 인증정보 미설정으로 503이며 실제 소셜 로그인 콜백은 시험하지 못했다. 개발용 로그인 검사를 소셜 로그인 검사로 대신하지 않는다.

PE·PS 베일의 업체 반입 근거 부족 3개 형태와 페놀수지·PU폼·고무의 미지원 경로는 남아 있다. 나머지 소재 전체의 인수·QR·완료를 웹에서 시험한 것도 아니다. 거리 표시는 직선거리이며 실물 운송이나 업체 허가·품질·법정 인증을 증명하지 않는다.
