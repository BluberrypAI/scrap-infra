## 새 웹 시나리오: A→B에서 완료

- A: 엔피씨 주식회사 화성공장 개발 계정. B: 독산 화성 개발 계정. 개발용 로그인으로 실제 계정을 바꿔 진행했다.
- 새 문진: `4df2197b63a449d89a9e1cee2b6426af`
- 새 lot: `11620610-e750-4657-89e1-e37736dceb13`
- 처리 건 URL: http://localhost:5178/wastes/case-4df2197b63a449d89a9e1cee2b6426af
- 자연어 PP 설명 → 문진 항목 14개 확인 → **51-03-01** 확정. 사진은 선택 항목이고 이번 새 건에는 첨부하지 않았다.
- **파쇄품 100kg**·상태 설명 저장 뒤에만 업체 검토·선택이 나온다. 공정 선택→사진→공정 재추천의 중복 흐름이 없다.
- Azure는 9개 공정·업체 조합을 검토했다. 8개 완료, HCR 파주 1개는 재시도 뒤에도 모델 응답 미완료로 남았다. 기존 8개 결과를 유지하고 미완료 업체 요청은 막았다. 미완료를 적합으로 바꾸지 않았다.
- 독산의 PP 분쇄품 투입·펠렛 생산 공개 근거가 확인됐고, 순도·수분·등급·현재 반입 승인은 계속 미확인으로 표시했다.
- B 계정 수락 → A 계정 **운송 시작** → QR 발급. 수락만으로 운송 처리하지 않는다.
- 발송 A로 QR 링크를 열면 **수신 기업 계정으로 로그인해야 한다**고 안내하며 입고 버튼이 없다.
- B로 같은 QR 링크를 열어 **입고 확인**. 현재 담당이 A에서 B로 바뀌고 처리 결과 입력이 열린다.
- B가 최종 **PP 펠렛 95kg**과 합성 작업 기록을 입력. 사진·업체 검토를 반복하지 않고 완료 근거·용도를 기록해 **완료**했다.
- 완료된 다섯 단계 모두 체크이며, 인수 요청·수락·운송·QR 발급·QR 입고·산출물·완료 **7건 이력**을 보존한다.
- A 출발 카카오 자동차 도로 **6.5km** 및 실제 도로를 따라 꺾이는 선을 표시했다. 실제 운송 GPS나 화물차 제한 검증은 아니다.

QR은 화면의 `링크 복사`로 얻은 URL을 해당 기업 로그인 상태에서 열었다. 휴대전화 카메라의 코드 인식 자체를 시험한 것은 아니다. QR 토큰은 문서·Git에 저장하지 않는다.

## 팀원이 실행하려면

형제 폴더 다섯 레포를 위 작업 브랜치로 맞춘 뒤 scrap-infra에서 기존 .env를 유지하고 실행한다.

```powershell
docker compose up -d --build
docker compose run --rm server-seed
```

브라우저는 **http://localhost:5178**. `127.0.0.1`로 바꾸지 않는다. 카카오 JS 키/REST 키와 Azure 값은 개인 .env 또는 배포 환경에 별도로 넣는다. Docker 이미지·Git에 키를 넣지 않았으므로 PR을 받는 것만으로 운영 키가 생기지 않는다. 상세 변수는 README와 .env.example 참조.

이 기록은 기능 연결 시험이다. 실제 업체 인증·허가·반입 가능 용량·계약 단가·현장 계량·법률 전문가 승인은 별도로 확보해야 한다. 손실 5kg의 별도 잔재 로트와 질량수지 전체 추적은 이번 시험 범위가 아니다. 운영 배포는 팀원의 릴리스 절차로 별도 진행한다.
